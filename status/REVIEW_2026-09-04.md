# volleytallyapp.com review, 2026-09-04

Reviewed by Claude Code (Fable 5.1 review). Read-only: clone of `main` at `15cac73`, GitHub API, live site headers, public store and link-association endpoints, and a read-only look at the Primary checkout.

## Executive summary

VolleyTally's standalone marketing and support site: 18 hand-written HTML pages, one CSS file plus token files, one 11-line JS file, and Apple/Android link-association files, deployed straight from `main` by GitHub Pages (legacy build, HTTPS enforced, `www` redirects, no Actions workflows of its own).
It is live and healthy at the transport level: every page and both `.well-known` files return 200 with the right content type, Apple's AASA CDN serves the domain, and Google's asset-links check returns the statement.
The site is ahead of the app: the App Store lists VolleyTally 3.4.2 (2026-07-10), while `/privacy/`, `/terms/`, and `/help/` already describe 4.0 Live broadcast, Firebase anonymous auth, and App Tracking Transparency. That breaks the README guardrail that claims must match the released app.
The home page still describes 3.x only, ships 3.5 MB of PNG screenshots with no lazy loading, and has no Terms or Help-index link in its nav or footer.
Most important next step: decide the 4.0 story once (either gate the Live copy until 4.0 is in both stores, or accept the gap and date it), then bring the home page and the image weight in line.

## Issues

### P0

None found.

### P1

1. **Site documents features the released app does not have.** `privacy/index.html`, `terms/index.html`, `help/index.html` (Live sharing sections, effective date July 18, 2026) vs. App Store version 3.4.2 released 2026-07-10 (iTunes lookup, verified today; Google Play version unverified). Fix: add a short "Available in VolleyTally 4.0" note to the Live sections now, and remove it when 4.0 is live in both stores. See Open question 1.
2. **Home page weight.** `index.html` loads `share-the-final.png` (2.1 MB), `score-every-rally.png` (640 KB), and `match-history.png` (356 KB) at 1320x2868 with no `loading="lazy"`, `width`/`height`, or `srcset`; roughly 3.5 MB of images on first paint. Fix: export WebP or resized PNG at ~660 px wide, add `width`/`height` and `loading="lazy"` below the fold.
3. **`status/CURRENT.md` misstates the Primary checkout.** The "3 dirty files" are untracked, not modified: `.DS_Store`, `.codex/config.toml`, and `drafts/2026-07-18-t4/` (four 4.0 legal and help drafts already published in `15e0723`). Fix: add a `.gitignore` with `.DS_Store` and `.codex/`, delete `drafts/` on the Primary, and correct `CURRENT.md`.

### P2

4. **Home page nav and footer omit Terms and the Help index.** `index.html` nav links `#help` (anchor) and `privacy/` only; footer has Privacy, Support, HarpElle. `/terms/` is reachable only from the help and privacy pages. Fix: add `terms/` to the footer and point the Help nav item at `help/`.
5. **Home page copy is 3.x only and Apple-leaning.** `index.html` OG and Twitter descriptions say "iPhone and iPad" while the page and app support Android; no mention of Live sharing; JSON-LD `downloadUrl` lists only the App Store. Fix: update the meta copy to "iPhone, iPad, and Android" and add a Live feature block when 4.0 ships (Plan step 4).
6. **Sitemap omits `/help/`.** `sitemap.xml` lists the six help articles but not the index that carries the Live help. Fix: add `<url><loc>https://volleytallyapp.com/help/</loc></url>`.
7. **Help index footer differs from every other page and uses an em-dash.** `help/index.html` footer reads "© 2026 HarpElle LLC — a HarpElle LLC product." Fix: use the shared footer "VolleyTally is a HarpElle LLC product."
8. **Third-party font request.** `tokens/fonts.css` imports Roboto Mono from `fonts.googleapis.com`, a third-party request on every page that `/privacy/` does not mention; also the `/live/` and `/watch/` pages style their code box as `'DM Mono'`, which is never loaded, so it falls back to generic monospace. Fix: self-host Roboto Mono (as harpelle.com already does) and change the `/live/` and `/watch/` font stack to `var(--font-numeral)`.
9. **Unused asset.** `assets/images/fix-a-stray-tap.png` (636 KB) is not referenced by any page. Fix: delete it or use it in the "Keep rallies moving" feature block.
10. **`data-track` attributes have no handler.** `index.html` tags four CTAs with `data-track` and README step 5 asks for analytics, but `assets/site.js` never reads them. Fix: either wire a privacy-respecting counter or remove the attributes and the README step. See Open question 2.
11. **`/watch/` PHASE flag is stale by design, not by accident.** `watch/index.html` `PHASE = 1` routes to VolleyTrack only; PHASE 2 (VolleyTally first) is gated on VolleyTally 4.0 being live. Not a bug today; record the trigger in the plan so it is not forgotten.
12. **CI cost is near zero but not zero.** No `.github/workflows`; GitHub's default-setup CodeQL runs weekly and on every push against a static site (about 1 minute per run, free for a public repo). Fix: optional, disable CodeQL default setup in repo settings if the noise is unwanted.
13. **Repo is public.** `HarpElle/volleytallyapp.com` is public (fine for a Pages site, and the content is public anyway); the `status/` folder is therefore public too. Keep internal decisions out of it.

## Suggestions (value over effort)

1. **Add a `.gitignore`** (`.DS_Store`, `.codex/`, `drafts/`). S, prevents the "dirty checkout" false alarm from recurring.
2. **Ship a 4.0 home page refresh with the app release**: Live sharing feature block, `/live/` explained in `help/saved-matches-and-sharing/`, refreshed screenshots from the 4.0 build, OG image updated. M, highest marketing value, gated on the release.
3. **Image pipeline**: a one-off `sips` or `cwebp` pass to ~660 px wide WebP plus PNG fallback; add `width`/`height` to stop layout shift. S, cuts first load by roughly 3 MB.
4. **Self-host the mono font** and drop the Google Fonts import. S, removes the only third-party request on the site and matches the harpelle.com pattern.
5. **Shared partials are hand-copied across 18 files** (header, footer, help nav). A tiny build step is not worth it yet; instead keep a `docs/PAGE_TEMPLATE.md` checklist so new pages get the same nav, footer, canonical, and OG tags. S.
6. **Add OG tags to `/privacy/` and `/terms/`** (both have canonicals but no `og:*` tags, so shared legal links render without a preview). S.

## Open questions for Jason

1. **How should the site handle the gap between published 4.0 content and the 3.4.2 store build?** Recommended: keep the legal pages as they are (they were published on purpose for review), add a one-line "Available starting with VolleyTally 4.0" note to the Live sections of `/help/` and `/privacy/`, and remove the note when 4.0 is live on both stores.
2. **Do you want analytics on this site at all?** Recommended: no third-party analytics; either remove the `data-track` attributes and README step 5, or reuse whatever privacy-respecting counter harpelle.com uses. The privacy policy currently does not mention site analytics, so adding any would need a policy line.
3. **Should `/watch/` flip to PHASE 2 (VolleyTally first) when 4.0 ships, or stay VolleyTrack-first for good?** Recommended: flip to PHASE 2 only after VolleyTally 4.0 with the `/watch/*` Universal Link claim is in both stores; until then leave it, since VolleyTrack coaches are the ones sharing `/watch/` links today.
4. **Is Google Play already on 4.0?** Unverified from here. If yes, item P1-1 shrinks to an iOS-only note.
